BaseAgent 是 nexus-sdk-ts 的核心 Agent 实现，基于 ReAct（Reasoning + Acting）模式，封装了"思考-工具调用-观察"的循环。

> 本文是 [`1. BaseAgent-通用的ReAct Agent.md`](./original/1.%20BaseAgent-通用的ReAct%20Agent.md)（Go 版）的 TypeScript 对应版本，基于 Bun + TS SDK 实际代码（`src/agent/base.ts`、`src/agent/option.ts`、`src/agent/agent.ts`）编写。文末附 **Go ↔ TS API 映射表**，并标注两版的差异点。

---
概述
BaseAgent 的运行流程（`loop()` in `src/agent/base.ts`）：
1. preHook：把渲染后的 instruction 作为首条 system 消息注入（仅一次）
2. 加载历史消息（`ctx.loadAllMessages()` → `filterEmptyMessage` → 可选 `filterMemory`）
3. 调用 `llm.generateContent()`（plan）
4. 检查响应：
   ├── 有 toolCalls → 逐个执行工具 → 结果回填 → 检查中断 → 继续循环
   ├── 无 toolCalls（最终答案）→ 跑 Feedback → 通过则返回，未通过回写提示重试
   └── 中断态为 Stop（如 askUser）→ 快照并优雅退出
5. 超过 maxIterations → 抛 `ErrMaxIterations`

创建 BaseAgent

```ts
import { BaseAgent } from "nexus-sdk-ts";

const agent = new BaseAgent({
  name: "my_agent",                 // 必须：唯一标识符（缺失抛 ErrMissingName）
  description: "我的 Agent 描述",     // 必须：功能描述（缺失抛 ErrMissingDesc）
  llm: llmClient,                   // 必须：LLM 实例（缺失抛 ErrMissingLLM）
  instruction: "系统提示词",          // 可选：作为首条 system 消息注入
  tools: myTools,                   // 可选：工具列表
  maxIterations: 30,                // 可选：最大循环次数（默认 30）
  callback: myCallback,             // 可选：事件 / 生命周期回调
  feedbacks: [myFeedback],          // 可选：输出质量反馈链
});
```

> 差异：Go 用 `NewBaseAgent(WithName(...), WithLLM(...))` 的函数式 Option 并返回 `(*BaseAgent, error)`；TS 用配置对象 + 构造函数，缺失必填字段时**直接抛异常**（`ErrMissingName` / `ErrMissingDesc` / `ErrMissingLLM`，见 `src/schema/errors.ts`）。

运行 Agent

```ts
// 签名（src/agent/agent.ts）
run(
  ctx: Context,
  messages: ChatCompletionMessage[],  // 必传；传 [] 表示只用 Context 已有消息
  opts?: GenerateOptions,
): Promise<ChatCompletionResponse>
```

场景 1：注入用户消息后运行

```ts
import { MemoryContext, newUserMessage } from "nexus-sdk-ts";

const ctx = new MemoryContext({ query: "请帮我分析这段代码" });
const resp = await agent.run(ctx, [newUserMessage(ctx.userQuery())]);
console.log(resp.message.content);
```

场景 2：覆盖 LLM 生成参数

```ts
const resp = await agent.run(ctx,
  [newUserMessage("基于之前的分析，给出最终建议")],
  { temperature: 0.1, maxTokens: 2000 },   // GenerateOptions
);
```

场景 3：在 Graph 节点中使用

```ts
import { gotoNode } from "nexus-sdk-ts";

g.addNode({
  name: "analysis",
  func: async (ctx, _registerStop, callback) => {
    const analyzer = new BaseAgent({
      name: "analyzer",
      description: "代码分析 Agent",
      llm: llmClient,
      callback,   // 继承 Graph 执行期传入的 callback
    });
    const resp = await analyzer.run(ctx, []);  // [] = 复用 Context 中已有消息
    ctx.set("analysis_result", resp.message.content ?? "");
    return gotoNode("report");
  },
});
```

> 差异：Go 的 `Run(ctx, nctx, messages, opts...)` 有 `ctx`/`nctx` 双上下文 + 变长 `GenerateOption`；TS 只有一个 `ctx: Context`，`opts` 是单个 `GenerateOptions` 对象，`messages` 为必传位置参数（用 `[]` 表示复用 Context）。

Human-in-Loop：run + resume

TS 版把 Go 里"askUser 工具触发中断 → 外部恢复"的能力做成了 `BaseAgent.resume()`：

```ts
import { BaseAgent, MemoryContext, newUserMessage, InterruptionType } from "nexus-sdk-ts";
import { AskUserTool } from "nexus-sdk-ts";

const ask = new AskUserTool();
const ctx = new MemoryContext({ tools: [ask] });
const agent = new BaseAgent({
  name: "travel-agent",
  description: "旅行推荐助手",
  instruction: "信息不足时先用 ask_user 工具向用户提问。",
  llm,
  askUserTool: ask,
});

// 1) 运行直到挂起
await agent.run(ctx, [newUserMessage("帮我推荐一个旅游城市")]);

const it = ctx.getInterruptionState();
if (it.interruptionType === InterruptionType.Stop) {
  console.log("Agent 提问：", it.question);
  // 2) 拿到用户回答后续跑
  const resp = await agent.resume(ctx, "我喜欢海边");
  console.log("最终答案：", resp.message.content);
}
```

> 差异：Go 通过 Graph 的中断快照 / 恢复机制驱动；TS 在 Agent 层直接提供 `resume(ctx, answer)`：它会把回答作为 user 消息追加、清空中断态（`interruptionType = None`、`isResumed = true`）后从中断点继续 ReAct 循环。完整示例见 [`examples/ask-user.ts`](../../examples/ask-user.ts)。

System Prompt 模板
`instruction` 经 `formatGoTemplate`（`src/prompt/go-template.ts`）渲染，支持 Go 风格占位符。BaseAgent 自动注入的变量：
变量
说明
{{ .name }}
Agent 名称
{{ .prompt }}
通过 `prompt` 选项注入的额外提示
{{ .current }}
当前时间（格式：`YYYY-MM-DD HH:mm:ss`）
{{ .with_context }}
`withContext` 为 true 时注入（默认 true）

`vars` 里的键也会一并注入，可在模板中用 `{{ .yourKey }}` 引用。默认指令模板见 `src/prompt/base-instruction.ts`（`DEFAULT_BASE_INSTRUCTION`），其中 `historical_roadmap` / `recent_roadmap` / `current_turn` 等占位符需由 `vars` 自行提供，否则渲染为空分支。

自定义系统提示：

```ts
const agent = new BaseAgent({
  name: "expert",
  description: "专业分析师",
  llm: llmClient,
  instruction: `你是 {{ .name }}，一个专业的数据分析师。
当前时间：{{ .current }}
{{ if .with_context }}
当前任务：{{ .current_turn }}
{{ end }}
{{ if .prompt }}
额外要求：{{ .prompt }}
{{ end }}`,
  vars: { domain: "金融数据" },   // 自定义变量
});
```

> 差异：Go 用 `text/template` + `go:embed` 的 `base_instruction.txt`；TS 用 `formatGoTemplate` 这一零依赖的等价渲染器（仅实现 `{{ .key }}` 变量、`{{ if }}/{{ else }}/{{ end }}` 条件），并把默认模板放在 `DEFAULT_BASE_INSTRUCTION` 常量里。注意：BaseAgent 只在有 `instruction` 时才注入 system 消息，且默认模板不会自动挂载，需显式 `instruction: DEFAULT_BASE_INSTRUCTION`。

工具配置

```ts
import { AbstractTool } from "nexus-sdk-ts";

class CalculatorTool extends AbstractTool {
  name() { return "calculator"; }
  description() { return "计算一个算术表达式"; }
  schema() {
    return {
      type: "object",
      properties: { expr: { type: "string", description: "算术表达式" } },
      required: ["expr"],
    };
  }
  async call(_ctx, args) {
    const { expr } = JSON.parse(args);
    return JSON.stringify({ expr, value: /* ... */ 0 });
  }
}

const agent = new BaseAgent({
  name: "coder",
  description: "代码助手",
  llm: llmClient,
  tools: [new CalculatorTool()],
});
```

工具去重：BaseAgent 在 `allTools()` 中合并 `opts.tools + ctx.getTools() + askUserTool`，按 `name()`（小写）去重。
Context 级工具：通过 `ctx.getTools()`（构造 `MemoryContext({ tools })` 注入）的工具会在每次 plan 时自动追加，无需在创建 Agent 时重复指定。

> 差异：Go 工具接口 `BaseTool` 在 TS 中对应同名接口（`src/tool/tool.ts`），`schema()` 返回 JSON Schema 对象（可由 zod-to-json-schema 生成），`call(ctx, args)` 的 `args` 是 JSON 字符串。

Feedback 配置
Feedback 在每轮产出后调用：最终答案分支未通过会把 `prompt` 作为 user 消息回写重试（受 `maxFeedbackRetries` 限制）；工具调用分支未通过则用 `prompt` 替换该工具结果。

```ts
import { JSONFeedback, FuncFeedback } from "nexus-sdk-ts";

const agent = new BaseAgent({
  name: "json_agent",
  description: "只输出 JSON",
  llm: llmClient,
  feedbacks: [
    new JSONFeedback(),                       // 校验最终输出是否为合法 JSON
    new FuncFeedback((content, toolCall) => {  // 自定义校验 / 工具拦截
      if (toolCall?.function.name === "danger") return { pass: false, prompt: "禁止调用该工具" };
      return { pass: true };
    }),
  ],
});
```

> 差异：Go 的 `feedback.Chain(...)` 在 TS 对应 `chain(...fds)`（`src/feedback/feedback.ts`），BaseAgent 内部自动用它把 `feedbacks` 串联，遇到第一个 `pass: false` 即短路。`JSONFeedback` / `FuncFeedback` 为内置实现。

历史消息过滤

```ts
const agent = new BaseAgent({
  name: "windowed",
  description: "只看最近 10 条",
  llm: llmClient,
  // 注意：TS 的 FilterMemoryFunc 只接收 messages，无 ctx
  filterMemory: (msgs) => (msgs.length <= 10 ? msgs : msgs.slice(-10)),
});
```

> 差异：Go 的 `FilterMemoryFunc = func(ctx, messages) []Message`；TS 的 `FilterMemoryFunc = (messages) => messages`，**不带 ctx**。它在 `filterEmptyMessage` 之后、喂给 LLM 之前生效。

优雅停止

```ts
// run() 进行中，从外部调用 stop()
setTimeout(() => agent.stop(), 5000);

// loop 在每次迭代开始时检查 shouldStop()，命中则跳出循环并返回当前响应
const resp = await agent.run(ctx, [newUserMessage("一个很长的任务")]);
```

在 Graph 节点中，可通过 `registerStop` 注册清理函数：

```ts
g.addNode({
  name: "long_task",
  func: async (ctx, registerStop) => {
    const a = new BaseAgent({ name: "worker", description: "长任务", llm: llmClient });
    registerStop(() => a.stop());   // Graph 关闭时自动停止 Agent
    await a.run(ctx, []);
    return null;
  },
});
```

> 差异：Go 的 `Stop()` 返回 `ErrStop`；TS 的 `stop()` 设置 `stopped = true` 并调用 `llm.stop()`，`shouldStop()` 还会把"中断态 != None"也视为停止条件 —— 即 loop 在每轮开头检测到 Stop 中断也会优雅退出（不抛异常，返回最近一次响应）。

---
注意事项
1. **名称唯一性**：同一流程中多个 Agent 应使用不同 `name`，否则消息命名空间会冲突。
2. **maxIterations 默认值**：默认 30 次。超出会抛 `ErrMaxIterations`（对应 Go 的 `ErrNotFinished`）。
3. **messages 必传**：`run(ctx, messages)` 的 `messages` 不能省略；复用 Context 已有消息时传 `[]`。
4. **instruction 只注入一次**：preHook 用 `__nexus_instruction_injected__` 标记位保证 system 指令只注入一次。
5. **中断即退出**：toolCall 执行后若 `ctx` 中断态为 Stop，会 `snapshotSession()` 并立即返回，由调用方决定何时 `resume`。
6. **无 AutoCompaction**：TS 版 BaseAgent 暂未实现 Go 的 `AutoCompaction` / `AutoContextEditing` 自动触发。
