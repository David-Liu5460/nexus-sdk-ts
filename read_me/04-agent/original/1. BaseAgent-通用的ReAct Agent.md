BaseAgent 是 Nexus SDK 中最核心的 Agent 实现，基于 ReAct（Reasoning + Acting）模式，封装了"思考-工具调用-观察"的完整循环。

> 📘 TypeScript 版本见 [`1. BaseAgent-通用的ReAct Agent (TS).md`](../1.%20BaseAgent-通用的ReAct%20Agent%20(TS).md)，基于 Bun + TS SDK 实际代码编写，含 Go ↔ TS API 映射表与差异标注。

---
概述
BaseAgent 的运行流程：
1. 构建 System Prompt（指令 + 历史 Roadmap）
2. 加载历史消息（从 Context 中读取）
3. 调用 LLM.GenerateContent()
4. 检查响应：
   ├── FinishReasonToolCalls → 执行工具 → 结果回填 → 继续循环
   ├── FinishReasonStop → 检查 Feedback → 通过则返回
   └── 其他（空响应等）→ 继续循环
5. 超过 MaxIterations → 返回 ErrNotFinished


---
创建 BaseAgent

```go
import "code.byted.org/ad/nexus/agent"
myAgent, err := agent.NewBaseAgent(
    agent.WithName("my_agent"),           // 必须：唯一标识符
    agent.WithDesc("我的 Agent 描述"),     // 必须：功能描述
    agent.WithLLM(llmClient),             // 必须：LLM 实例
    agent.WithInstruction("系统提示词"),   // 可选：覆盖默认系统提示
    agent.WithTools(myTools),             // 可选：工具列表
    agent.WithMaxIterations(30),          // 可选：最大循环次数（默认 30）
    agent.WithCallback(myCallback),       // 可选：事件回调
    agent.WithFeedbacks(myFeedback),      // 可选：输出质量反馈
)
if err != nil {
    // 可能的错误：ErrMissingName、ErrMissingDesc、ErrMissingLLM
    panic(err)
}
```

运行 Agent

```go
// 签名
func (a *BaseAgent) Run(
    ctx context.Context,
    nexusCtx schema.Context,
    messages []schema.ChatCompletionMessage,  // nil = 使用 Context 中已有消息
    opts ...schema.GenerateOption,
) (*schema.ChatCompletionResponse, error)
```

场景 1：使用 Context 中已有消息

```go
// 先向 Context 中添加消息
nctx.AddMessage("user", schema.ChatCompletionMessage{
    Role:    schema.ChatMessageRoleUser,
    Content: "请帮我分析这段代码",
})
// 传 nil，Agent 自动从 Context 加载消息
response, err := myAgent.Run(ctx, nctx, nil)
```

场景 2：注入额外消息（节点层级 Mock）

```go
// 在节点中注入消息，覆盖或补充 Context
response, err := myAgent.Run(ctx, nctx,
    []schema.ChatCompletionMessage{
        llm.NewUserMessage("node", "基于之前的分析，给出最终建议"),
    },
    llm.WithTemperature(0.1),   // 覆盖 LLM 参数
    llm.WithMaxTokens(2000),
)
```

场景 3：在 Graph 节点中使用

```go
g.AddNode("analysis", func(ctx context.Context, nctx schema.Context,
    reg func(func(schema.Context)), cb schema.Callback) (*schema.Command, error) {
    analyzer, _ := agent.NewBaseAgent(
        agent.WithName("analyzer"),
        agent.WithDesc("代码分析 Agent"),
        agent.WithLLM(llmClient),
        agent.WithCallback(cb),  // 继承 Graph 的 callback
    )
    resp, err := analyzer.Run(ctx, nctx, nil)
    if err != nil {
        return nil, err
    }
    result := resp.Choices[0].Message.Content
    nctx.Set("analysis_result", result)
    return schema.GotoNode("report"), nil
})
```

---
System Prompt 模板
默认系统提示词（agent/prompts/base_instruction.txt）支持以下变量：
变量
说明
{{.name}}
Agent 名称
{{.prompt}}
通过 WithPrompt() 注入的额外提示
{{.current}}
当前时间（格式：2006-01-02 15:04:05）
{{.with_context}}
是否有历史上下文（仅 WithContextInInstruction(true) 时注入）
{{.historical_roadmap}}
历史压缩层的摘要（仅 WithContextInInstruction(true) 时注入）
{{.recent_roadmap}}
近期对话层的摘要（仅 WithContextInInstruction(true) 时注入）
{{.current_turn}}
当前轮次的摘要（仅 WithContextInInstruction(true) 时注入）
{{.current_turn_id}}
当前轮次 ID（仅 WithContextInInstruction(true) 时注入）
Roadmap 注入控制：

默认情况下（WithContextInInstruction(true)），Plan() 会将 Context 的 Roadmap 路径（historical_roadmap、recent_roadmap、current_turn、current_turn_id）注入到系统指令模板变量中，使 LLM 能感知完整的多轮对话历史。

设为 false 时，这些变量不会被注入，适用于：

- 无状态场景（每次调用完全独立，不需要历史上下文）
- 自定义 Prompt 不包含上述变量时，避免无效渲染
- 需要减少 System Prompt 长度以节省 Token 时

```go
// 关闭 Roadmap 注入（适合无状态 Agent）
myAgent, _ := agent.NewBaseAgent(
    agent.WithName("stateless_agent"),
    agent.WithDesc("无状态处理 Agent"),
    agent.WithLLM(llmClient),
    agent.WithContextInInstruction(false),
)
```

自定义系统提示：

```go
myAgent, _ := agent.NewBaseAgent(
    agent.WithName("expert"),
    agent.WithDesc("专业分析师"),
    agent.WithLLM(llmClient),
    agent.WithInstruction(`你是 {{.name}}，一个专业的数据分析师。
当前时间：{{.current}}
{{if .with_context}}

    agent.WithVar("domain", "金融数据"),  // 自定义变量

```

工具配置

```go
import (
    "code.byted.org/ad/nexus/tool/file"
    "code.byted.org/ad/nexus/tool/rag"
)
// 创建工具
readTool := file.NewFileReadTool()
writeTool := file.NewFileWriteTool()
ragTool, _ := rag.NewByteRAGTool(rag.WithKnowledgeBase("kb-001"))
// 注册给 Agent
myAgent, _ := agent.NewBaseAgent(
    agent.WithName("coder"),
    agent.WithDesc("代码助手"),
    agent.WithLLM(llmClient),
    agent.WithTools([]schema.BaseTool{readTool, writeTool, ragTool}),
)
```

工具去重：BaseAgent 自动对工具列表去重（按 Name() 去重），无需手动处理。
Context 级工具：通过 nctx.GetTools() 获取的工具会在每次 Plan() 时自动追加，无需在创建 Agent 时指定。

Feedback 配置
Feedback 在 Agent 每轮输出后调用，可阻止不符合质量要求的输出并要求重新生成：

```go
import "code.byted.org/ad/nexus/feedback"
// 使用内置 JSON Feedback
myAgent, _ := agent.NewBaseAgent(
    // ...
    agent.WithFeedbacks(
        feedback.NewJSONFeedback(),  // 验证输出是否为合法 JSON
    ),
)
// 多个 Feedback 串联
myAgent, _ := agent.NewBaseAgent(
    // ...
    agent.WithFeedbacks(
        feedback.NewJSONFeedback(),
        myCustomFeedback,
    ),
)
```

历史消息过滤

```go
// FilterMemoryFunc 类型定义
type FilterMemoryFunc = func(ctx context.Context, messages []schema.ChatCompletionMessage) []schema.ChatCompletionMessage
// 示例：只保留最近 10 条消息
myAgent, _ := agent.NewBaseAgent(
    // ...
    agent.WithFilterMemoryFunc(func(ctx context.Context, msgs []schema.ChatCompletionMessage) []schema.ChatCompletionMessage {
        if len(msgs) <= 10 {
            return msgs
        }
        return msgs[len(msgs)-10:]
    }),
)
```

优雅停止

```go
// 在另一个 goroutine 中停止 Agent
go func() {
    time.Sleep(5 * time.Second)
    myAgent.Stop()  // 设置 stop 标志
}()
// Run 会在下一个循环开始时检查 stop 标志，返回 ErrStop
resp, err := myAgent.Run(ctx, nctx, nil)
if errors.Is(err, schema.ErrStop) {
    // Agent 被停止
}
```

在 Graph 节点中，可通过 registerStopFunc 注册清理函数：

```go
g.AddNode("long_task", func(ctx context.Context, nctx schema.Context,
    reg func(func(schema.Context)), cb schema.Callback) (*schema.Command, error) {
    // 创建 Agent
    a, _ := agent.NewBaseAgent(...)
    // 注册停止函数：当 Graph.Close() 被调用时，自动停止 Agent
    reg(func(nctx schema.Context) {
        a.Stop()
    })
    return nil, a.Run(ctx, nctx, nil) // 简化，实际需处理响应
})
```

---
注意事项
1. 名称唯一性：同一 Graph 中多个 Agent 应使用不同名称，否则消息命名空间会冲突。
2. MaxIterations 默认值：默认 30 次，适合大多数场景。对于简单 Q&A，可设为 3-5。
3. Context 命名空间：每个 BaseAgent 实例有唯一的 namespace（短 hash），消息按此分组存储。
4. AutoCompaction 自动触发：Run() 完成后自动触发 AutoCompaction()，无需手动调用。
5. AutoContextEditing 在工具调用后触发：每次工具调用完成后自动触发，帮助管理 Token。
