nexus-sdk-ts 的图编排天然支持多 Agent 协作：不同 Agent 作为独立节点，通过共享 `Context` 传递状态。

> 本文是 [`5. 基于Graph的Multi Agent示例.md`](./original/5.%20基于Graph的Multi%20Agent示例.md)（Go 版）的 TypeScript 对应版本，基于 Bun + TS SDK 实际代码（`src/agent/base.ts`、`src/context/context.ts`、`src/core/graph.ts`）编写。文末附 **Go ↔ TS API 映射表**，并标注两版的差异点。

---
TS 版 Agent API 速览

与 Go 的 functional-options 风格不同，TS 的 `BaseAgent` 用**构造对象**创建，`run` 显式接收消息数组：

```ts
import { BaseAgent } from "nexus-sdk-ts";

const agent = new BaseAgent({
  name: "analyzer",
  description: "需求分析 Agent",
  llm: llmClient,        // 必填，缺失会抛 ErrMissingLLM
  tools: [],             // 可选
  callback: cb,          // 可选
  maxIterations: 30,     // 可选，默认 30
});

// run(ctx, messages, opts?) -> Promise<ChatCompletionResponse>
const resp = await agent.run(ctx, [newUserMessage("...")]);
const answer = resp.message.content;
```

> ⚠️ 关键差异：TS 的 `AgentOptions`（`src/agent/option.ts`）**没有** `instruction` / `WithInstruction` 字段。Go 的 `WithInstruction("...")` 系统提示在 TS 版需通过**消息**注入——即在 `run` 的 `messages` 里传入 `newSystemMessage("...")`，或事先 `ctx.addMessage(...)`。

---
多 Agent 协作模式

模式 1：顺序协作（流水线）

每个 Agent 依次执行，上一个的输出经 `ctx` 传给下一个：

```ts
import {
  Graph, MemoryContext, BaseAgent, END,
  newSystemMessage, newUserMessage,
} from "nexus-sdk-ts";

async function main() {
  const llmClient = buildLLM(); // 见 examples/agent-tools.ts 的 LLM 构造

  const g = new Graph();

  // Agent 1：需求分析
  g.addNode({
    name: "analyzer",
    func: async (ctx, _registerStop, cb) => {
      const a = new BaseAgent({
        name: "analyzer",
        description: "需求分析 Agent",
        llm: llmClient,
        callback: cb, // 把图的 callback 透传给节点内 Agent
      });
      const resp = await a.run(ctx, [
        newSystemMessage("分析用户需求，提取关键信息。"), // 替代 Go 的 WithInstruction
        newUserMessage(ctx.userQuery()),
      ]);
      ctx.set("analysis", resp.message.content);
      return null; // 用静态边路由到 planner
    },
  });

  // Agent 2：计划制定
  g.addNode({
    name: "planner",
    func: async (ctx, _registerStop, cb) => {
      const analysis = ctx.get<string>("analysis")!;
      const p = new BaseAgent({
        name: "planner",
        description: "计划制定 Agent",
        llm: llmClient,
        callback: cb,
      });
      const resp = await p.run(ctx, [
        newSystemMessage("基于需求分析，制定具体的执行计划。"),
        newUserMessage(`需求分析结果：${analysis}\n请制定执行计划。`),
      ]);
      ctx.set("plan", resp.message.content);
      return null;
    },
  });

  // Agent 3：执行总结
  g.addNode({
    name: "executor",
    func: async (ctx, _registerStop, cb) => {
      const plan = ctx.get<string>("plan")!;
      const e = new BaseAgent({
        name: "executor",
        description: "执行总结 Agent",
        llm: llmClient,
        callback: cb,
      });
      const resp = await e.run(ctx, [
        newSystemMessage("将计划转化为可执行的步骤清单。"),
        newUserMessage(`执行计划：${plan}\n请生成详细步骤。`),
      ]);
      ctx.set("final_output", resp.message.content);
      return null;
    },
  });

  g.addEdge("analyzer", "planner");
  g.addEdge("planner", "executor");
  g.addEdge("executor", END);
  g.setEntryPoint("analyzer");

  // 初始查询经 Context 注入（而非 invoke 参数）
  const ctx = new MemoryContext({ query: "帮我制定一个学习 TypeScript 的计划" });
  await g.compile().invoke(ctx);

  console.log("最终输出:", ctx.get<string>("final_output"));
}

main().catch((e) => { console.error(e); process.exit(1); });
```

> 差异：Go 的 `app.Invoke(ctx, message)` 会把初始消息注入 Context；TS 的 `invoke(ctx, opts?)` **不注入消息**，初始查询通过 `new MemoryContext({ query })` 提供，节点内用 `ctx.userQuery()` 读取。

模式 2：监督者-工作者（Supervisor-Worker）

Supervisor Agent 决定调用哪个 Worker，用 `gotoNode` 动态路由：

```ts
import { gotoNode } from "nexus-sdk-ts";

g.addNode({
  name: "supervisor",
  func: async (ctx, _registerStop, cb) => {
    const supervisor = new BaseAgent({
      name: "supervisor",
      description: "任务分派主管",
      llm: llmClient,
      callback: cb,
    });
    const resp = await supervisor.run(ctx, [
      newSystemMessage(`你是一个任务分派主管。根据用户请求，决定分配给哪个专家：
- code_expert: 编程相关问题
- math_expert: 数学计算问题
- writing_expert: 文字创作问题
请直接输出专家名称。`),
      newUserMessage(ctx.userQuery()),
    ]);
    const nextAgent = resp.message.content.trim();
    return gotoNode(nextAgent); // 动态路由到对应专家节点
  },
});

g.addNode({ name: "code_expert", func: codeExpertFunc });
g.addNode({ name: "math_expert", func: mathExpertFunc });
g.addNode({ name: "writing_expert", func: writingExpertFunc });

// 各专家汇聚到 output
g.addEdge("code_expert", "output");
g.addEdge("math_expert", "output");
g.addEdge("writing_expert", "output");
g.addEdge("output", END);
g.setEntryPoint("supervisor");
```

---
多 Agent 共享 Context

共享状态（Shared State）—— 所有 Agent 可读写，适合传递中间结果：

```ts
// Agent A 写入
ctx.setShared("analysis_result", analysisData);
// Agent B 读取
const result = ctx.getShared<typeof analysisData>("analysis_result");
```

私有状态（Private State）—— 隔离写入，避免并行竞态：

```ts
// 写入私有状态
ctx.setPrivate("agent_a_result", resultA);
// 读取自己的私有状态
const r = ctx.getPrivate<typeof resultA>("agent_a_result");
```

> 差异：Go 的私有状态按 Agent 名分命名空间——`SetPrivate("agent_a", "key", val)`（**三参**）；TS 的 `setPrivate(key, value)` 是**两参**，无显式 Agent 命名空间维度（见 `src/context/context.ts`）。需要隔离时请自行用带前缀的 key（如 `"agent_a:result"`）。

---
注意事项

1. **并行节点的竞态**：并行执行时（`gotoNodes` 或一个节点配多条 `addEdge`），多个 Agent 同时写同一个 shared key 会竞态。JS 虽单线程，但 `await` 间隙仍可能读到旧值——并行分支建议写不同 key 或用 `setPrivate`。
2. **系统提示走消息**：TS 无 `instruction` 选项，Go 的 `WithInstruction` 一律改为 `newSystemMessage(...)` 放进 `run` 的 messages。
3. **Callback 透传**：节点函数第三个参数是 `callback`，建议传给节点内创建的 Agent（`new BaseAgent({ callback: cb })`），以保证事件流完整。
4. **llm 必填**：`BaseAgent` 缺少 `llm` 会在 `run` 时抛 `ErrMissingLLM`；超过 `maxIterations`（默认 30）抛 `ErrMaxIterations`。
5. **避免深度递归**：图执行是递归的（`execute`），嵌套 Graph 层级过深可能触发调用栈上限；`invoke` 另有 `maxSteps`（默认 1000）防止 `goto` 自环。

Go ↔ TS API 映射表

| Go API | TS API |
| --- | --- |
| `agent.NewBaseAgent(WithName(...), WithLLM(...), ...)` | `new BaseAgent({ name, llm, ... })` |
| `agent.WithInstruction("...")` | **无此选项**，改用 `newSystemMessage("...")` 放进 `run` 的消息 |
| `agent.WithCallback(cb)` | `new BaseAgent({ callback: cb })` |
| `a.Run(ctx, nctx, nil)` | `a.run(ctx, messages)` —— 单 ctx，消息显式传 |
| `a.Run(ctx, nctx, []ChatCompletionMessage{...})` | `a.run(ctx, [newUserMessage(...)])` |
| `resp.Choices[0].Message.Content` | `resp.message.content` |
| `llm.NewUserMessage(ns, text)` | `newUserMessage(text)`（无 namespace 参数） |
| `nctx.SetShared / GetShared` | `ctx.setShared / getShared<T>` |
| `nctx.SetPrivate("agentA", "k", v)`（三参） | `ctx.setPrivate("k", v)`（两参，无命名空间） |
| `schema.GotoNode(x)` | `gotoNode(x)` |
| `app.Invoke(ctx, message)`（注入消息） | `invoke(ctx, opts?)`（消息走 `new MemoryContext({ query })`） |
| `g.AddNode("n", fn)` | `g.addNode({ name: "n", func: fn })` |
