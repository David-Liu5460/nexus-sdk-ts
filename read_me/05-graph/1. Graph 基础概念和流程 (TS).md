Graph 是 nexus-sdk-ts 的编排层，通过有向图将多个节点（Node）连接成可执行的工作流。

> 本文是 [`1. Graph 基础概念和流程.md`](./1.%20Graph%20基础概念和流程.md)（Go 版）的 TypeScript 对应版本，基于 Bun + TS SDK 实际代码编写。文末附 **Go ↔ TS API 映射表**，并标注两版的差异点。

---
核心概念
概念
说明
Graph
有向图结构，包含节点、边（`src/core/graph.ts`）
Node
图中的执行单元，封装 NodeFunc（`src/core/node.ts`）
NodeFunc
节点的实际执行逻辑，返回 `Command | null` 控制路由
Edge
静态有向边，连接两个节点
ConditionalEdge
运行时决定路由的条件边（`ConditionFunc`）
Application
编译后的可执行图，调用 `invoke()` 运行（`src/core/application.ts`）
Command
节点返回的路由控制命令（`src/core/command.ts`）

---
图的生命周期
1. 创建: `new Graph(opts?)`
2. 定义: `addNode` / `addEdge` / `addConditionalEdge`
3. 配置: `setEntryPoint`
4. 编译: `g.compile()` → `Application`（验证入口点）
5. 执行: `app.invoke(ctx, opts?)`
6. 关闭: Node 上有可选 `close()` 钩子（当前 SDK 暂未自动触发，需自行调用）

---
创建图

```ts
import { Graph } from "nexus-sdk-ts";

// 基础创建
const g = new Graph();

// 带选项创建（仅 namespace；Context 与 Callback 不在此处传）
const g2 = new Graph({ namespace: "my-workflow" }); // 默认 "default"
```

> 差异：Go 的 `NewGraph(nctx, ...)` 在构造时绑定 Context 和 Callback；TS 版 Graph 只持有结构（namespace），Context 与 Callback 都在 `invoke()` 时传入。

---
添加节点
NodeFunc 签名（TS）：

```ts
import type { Context, Callback, Command, RegisterStopFunc } from "nexus-sdk-ts";

type NodeFunc = (
  ctx: Context,
  registerStop: RegisterStopFunc, // 注册清理函数：(fn: () => void) => void
  callback?: Callback,
) => Promise<Command | null>;     // 返回 null = 使用边决定路由
```

```ts
// 基础节点
g.addNode({
  name: "my_node",
  func: async (ctx) => {
    // 读取状态
    const input = ctx.get<string>("input")!;
    // 执行逻辑
    const result = process(input);
    // 写入状态
    ctx.set("result", result);
    // 返回路由命令（null = 使用边决定路由）
    return null;
  },
});

// 带节点配置
g.addNode({
  name: "risky_node",
  func: myNodeFunc,
  config: {
    timeoutMs: 30_000,   // 节点超时（省略/0 = 不限）
    maxRetries: 3,       // 失败重试次数（默认 0 = 不重试）
    retryDelayMs: 2_000, // 重试间隔
    skipOnError: false,  // true = 出错时跳过（继续执行）
  },
});
```

> 差异：Go 的 NodeFunc 有 `ctx context.Context` 和 `nctx schema.Context` 两个上下文参数；TS 只有一个 `ctx: Context`。配置字段名也不同（`Timeout`→`timeoutMs`、`RetryDelay`→`retryDelayMs`，单位为毫秒）。

---
添加边
静态边（一对一）

```ts
// 顺序边：A → B
g.addEdge("nodeA", "nodeB");
// 到终点
g.addEdge("lastNode", END);
```

并行边（一对多）

```ts
// TS 的 addEdge 不支持多目标，分多次声明即可
// A 有两条出边 → B、C 在下一波并发执行
g.addEdge("nodeA", "nodeB");
g.addEdge("nodeA", "nodeC");

// 或在节点里用 Command 动态并发
import { gotoNodes } from "nexus-sdk-ts";
return gotoNodes("nodeB", "nodeC");
```

条件边

```ts
import type { Context } from "nexus-sdk-ts";

// ConditionFunc 类型：(ctx) => string | string[]
g.addConditionalEdge("router", (ctx: Context) => {
  const category = ctx.get<string>("category");
  switch (category) {
    case "urgent": return "urgent_handler";
    case "normal": return "normal_handler";
    default:       return "default_handler";
  }
});
```

> 差异：Go 的条件边返回 `([]string, error)`；TS 的 `ConditionFunc` 同步返回 `string | string[]`，不带 error。

设置入口点

```ts
g.setEntryPoint("first_node");
```

---
Pipeline 快捷方法

> ⚠️ TS 版 **未内置** `Pipeline`。等价写法是手动串联：

```ts
// 等价于 Go 的 g.Pipeline(step1, step2, step3)
g.addNode({ name: "step1", func: step1Func });
g.addNode({ name: "step2", func: step2Func });
g.addNode({ name: "step3", func: step3Func });
g.addEdge("step1", "step2");
g.addEdge("step2", "step3");
g.addEdge("step3", END);
g.setEntryPoint("step1");
```

---
编译

```ts
// compile() 失败时抛异常（不是返回 error）
try {
  const app = g.compile();
} catch (e) {
  // 可能的错误：
  // "entry point not set"            - 未设置入口点
  // "entry point node not found: x"  - 入口点未注册
  throw e;
}
```

> 差异：Go 返回 `(*Application, error)`；TS 直接返回 `Application`，校验失败 `throw new Error(...)`。

---
执行

```ts
import { MemoryContext } from "nexus-sdk-ts";

// 1) 初始消息 / 用户查询通过 Context 注入（而非 invoke 的参数）
const ctx = new MemoryContext({ query: "用户的查询" });
// 如需注入完整消息：ctx.addMessage({ role: "user", content: "用户的查询" });

// 2) invoke 只接收 ctx 与可选项（callback / maxSteps）
await app.invoke(ctx, {
  // callback: myCallback,
  // maxSteps: 1000,   // 防御性递归上限，默认 1000
});
```

`invoke` 的执行流程（TS 实际行为）：
1. 从 `entryPoint` 开始，递归按层执行节点（`execute`）
2. 每一波节点用 `Promise.all` 并发执行（含重试 / 超时 / skipOnError）
3. 每波结束后检查 `ctx.getInterruptionState()`，为 `Stop` 时记录 `currentNode` 并退出
4. 按 `Command.goto > 条件边 > 静态边 > END` 解析下一波节点
5. 下一波为空 → 结束

> 差异（TS 版尚未实现的 Go 流程）：
> - **不**自动注入初始消息（Go 的 `Invoke(ctx, message)` 会把 message 加入 Context）
> - **无** `GraphStartCallback` / `GraphEndCallback`
> - **无** `AutoCompaction` 与自动 `Context.Release()`
> - 中断恢复目前只记录 `currentNode`，尚未实现"从 CurrentNode 重新开始"的 resume 逻辑

---
完整示例：三步流水线

```ts
import { Graph, MemoryContext, END } from "nexus-sdk-ts";

async function main() {
  const g = new Graph();

  // 节点 1：预处理
  g.addNode({
    name: "preprocess",
    func: async (ctx) => {
      ctx.set("processed", "预处理完成");
      console.log("[Step 1] 预处理");
      return null;
    },
  });

  // 节点 2：主逻辑
  g.addNode({
    name: "main_logic",
    func: async (ctx) => {
      const input = ctx.get<string>("processed")!;
      ctx.set("result", `${input} → 主逻辑处理完成`);
      console.log("[Step 2] 主逻辑");
      return null;
    },
  });

  // 节点 3：后处理
  g.addNode({
    name: "postprocess",
    func: async (ctx) => {
      const result = ctx.get<string>("result")!;
      console.log(`[Step 3] 后处理，最终结果：${result}`);
      return null;
    },
  });

  // 顺序边
  g.addEdge("preprocess", "main_logic");
  g.addEdge("main_logic", "postprocess");
  g.addEdge("postprocess", END);
  g.setEntryPoint("preprocess");

  const app = g.compile();
  const ctx = new MemoryContext({ query: "用户的查询" });
  await app.invoke(ctx);

  console.log("最终状态:", ctx.map());
}

main().catch((e) => { console.error(e); process.exit(1); });
```

---
状态在节点间传递
所有节点通过共享的 `ctx`（Context）传递状态：

```ts
// 节点 A：写入状态
ctx.set("my_key", "my_value");
ctx.setShared("global_key", 42);

// 节点 B（在 A 之后执行）：读取状态
const value = ctx.get<string>("my_key");
const num = ctx.getShared<number>("global_key");

// 私有状态（并行节点隔离写入，避免竞态）
ctx.setPrivate("step_local", { tries: 1 });
const local = ctx.getPrivate<{ tries: number }>("step_local");
```

> 补充：TS Context 提供三档状态 —— `set/get`（默认）、`setShared/getShared`（全局共享）、`setPrivate/getPrivate`（私有隔离）。Go 版同样有 Shared/Private 概念。

---
图执行错误处理

```ts
// 方式 1：节点出错，图终止（默认）
// NodeFunc 抛出异常且未配置容错 → 图停止，invoke reject

// 方式 2：出错跳过（skipOnError = true）
g.addNode({
  name: "optional",
  func: myFunc,
  config: { skipOnError: true }, // 出错时该节点返回 null，图继续
});

// 方式 3：超时重试
g.addNode({
  name: "flaky",
  func: myFunc,
  config: {
    timeoutMs: 10_000,
    maxRetries: 3,
    retryDelayMs: 1_000,
  },
});
```

> 实现位置：节点级容错在 `executeNode`（`src/core/application.ts`）中处理 —— 重试用循环 + 延时，超时用 `AbortController` + `Promise.race`，`skipOnError` 失败时返回 `null`。

---
注意事项
1. **构造与执行解耦**：Graph 构造时不持有 Context/Callback；它们在 `invoke(ctx, { callback })` 时传入。
2. **入口点必须先注册**：`setEntryPoint` 指向的节点必须已 `addNode`，否则 `compile()` 抛异常。
3. **END 是保留节点名**：`END = "END"`（`src/core/command.ts`），不能作普通节点名。
4. **重复节点名**：`addNode` 同名节点会抛 `duplicate node`。
5. **并行节点共享 Context**：JS 单线程下不会真并发写，但 `await` 间隙可能读到旧值；并行节点建议写不同 key 或用 `setPrivate`。
6. **递归上限**：`invoke` 默认 `maxSteps = 1000`，防止 `goto` 自环导致无限递归。
