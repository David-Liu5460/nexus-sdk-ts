GraphMiddleware 是图级别的全局执行拦截器，在每个节点执行前被调用，可以动态改变下一步的路由目标。

---
中间件接口
// GraphMiddleware 签名
type GraphMiddleware func(
    ctx context.Context,
    nexusCtx Context,
    currentNode string,   // 当前即将执行完的节点名
    callback Callback,
) string  // 返回重定向的目标节点名（"" = 不拦截，继续正常路由）

---
添加中间件
g := schema.NewGraph(nctx)
// 添加单个中间件
g.AddMiddlewares(myMiddleware)
// 添加多个中间件（按顺序串联）
g.AddMiddlewares(authMiddleware, loggingMiddleware, ratelimitMiddleware)
链式调用：多个中间件按添加顺序执行，第一个返回非空字符串的中间件生效，后续中间件不再执行。

---
中间件示例
示例 1：日志中间件
loggingMiddleware := func(ctx context.Context, nctx schema.Context,
    currentNode string, cb schema.Callback) string {
    log.Printf("[Graph] 节点 '%s' 执行完毕，当前状态: %v", currentNode, nctx.Map())
    return "" // 不改变路由
}
g.AddMiddlewares(loggingMiddleware)
示例 2：全局错误恢复（Fallback）
// 当图检测到错误状态时，强制路由到错误处理节点
errorFallbackMiddleware := func(ctx context.Context, nctx schema.Context,
    currentNode string, cb schema.Callback) string {
    if errMsg, ok := nctx.GetShared("error"); ok && errMsg != nil {
        // 避免死循环：如果已经在错误处理节点，不再重定向
        if currentNode != "error_handler" {
            return "error_handler"
        }
    }
    return ""
}
g.AddMiddlewares(errorFallbackMiddleware)
示例 3：速率限制
var (
    requestCount int64
    mu           sync.Mutex
)
rateLimitMiddleware := func(ctx context.Context, nctx schema.Context,
    currentNode string, cb schema.Callback) string {
    mu.Lock()
    requestCount++
    count := requestCount
    mu.Unlock()
    if count > 100 {
        // 超过速率限制，路由到等待节点
        log.Printf("Rate limit exceeded at node '%s'", currentNode)
        return "rate_limit_handler"
    }
    return ""
}
示例 4：A/B 测试路由
abTestMiddleware := func(ctx context.Context, nctx schema.Context,
    currentNode string, cb schema.Callback) string {
    // 只在特定节点后介入
    if currentNode != "user_input" {
        return ""
    }
    userID, _ := nctx.GetShared("user_id")
    if userID != nil && hash(userID.(string)) % 2 == 0 {
        // 50% 的用户走新版本
        return "new_flow"
    }
    return "" // 其他用户走正常流程
}

---
中间件链
GraphMiddlewareChain 将多个中间件组合为一个：
// 手动组合（内部使用）
combined := schema.GraphMiddlewareChain(mw1, mw2, mw3)
g.AddMiddlewares(combined)
// 等价于分步添加
g.AddMiddlewares(mw1, mw2, mw3)

---
中间件的限制
1. 不能创建循环：中间件不能将节点路由回自身（currentNode != target 时才生效）。代码中有防护：
// 源码中的防护
if target != "" && currentNode != target {
    return []string{target}, nil
}
2. 只能在节点执行后调用：中间件在 NodeFunc 执行完毕、确定下一个节点时触发，不能在节点执行前拦截。
3. 全局作用域：中间件对图中的所有节点生效，需要在函数内部判断 currentNode 来针对特定节点处理。
4. 第一个返回值生效：多个中间件中，第一个返回非空字符串的中间件决定路由，其余中间件不执行。
