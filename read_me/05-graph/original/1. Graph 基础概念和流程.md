Graph 是 Nexus SDK 的编排层，通过有向图将多个节点（Node）连接成可执行的工作流。

---
核心概念
概念
说明
Graph
有向图结构，包含节点、边和中间件
Node
图中的执行单元，封装 NodeFunc
NodeFunc
节点的实际执行逻辑，返回 *Command 控制路由
Edge
静态有向边，连接两个节点
ConditionalEdge
运行时决定路由的条件边
Application
编译后的可执行图，调用 Invoke() 运行
Command
节点返回的路由控制命令


---
图的生命周期
1. 创建: schema.NewGraph(nctx, opts...)
2. 定义: AddNode / AddEdge / AddConditionalEdge
3. 配置: SetEntryPoint / AddMiddlewares
4. 编译: g.Compile() → *Application（验证图结构）
5. 执行: app.Invoke(ctx, message)
6. 关闭: g.Close()（可选，触发节点清理函数）

---
创建图

```go
import (
    "code.byted.org/ad/nexus/context/nexuscontext"
    "code.byted.org/ad/nexus/schema"
)
nctx := &nexuscontext.NexusContext{}
// 基础创建
g := schema.NewGraph(nctx)
// 带选项创建
g := schema.NewGraph(nctx,
    schema.WithCallback(myCallback),
    schema.WithNamespace("my-workflow"),  // 消息命名空间（默认 "graph"）
)
```

---
添加节点
NodeFunc 签名（固定，不可更改）：

```go
type NodeFunc func(
    ctx context.Context,
    nctx schema.Context,
    registerStopFunc func(func(nctx schema.Context)),  // 注册清理函数
    callback schema.Callback,
) (*schema.Command, error)
// 基础节点
g.AddNode("my_node", func(ctx context.Context, nctx schema.Context,
    reg func(func(schema.Context)), cb schema.Callback) (*schema.Command, error) {
    // 读取状态
    input := nctx.Get("input").(string)
    // 执行逻辑
    result := process(input)
    // 写入状态
    nctx.Set("result", result)
    // 返回路由命令（nil = 使用边决定路由）
    return nil, nil
})
// 带节点配置
import "time"
g.AddNode("risky_node", myNodeFunc, schema.NodeConfig{
    Timeout:     30 * time.Second,   // 节点超时（0 = 不限）
    MaxRetries:  3,                   // 失败重试次数（0 = 不重试）
    RetryDelay:  2 * time.Second,    // 重试间隔
    SkipOnError: false,               // true = 出错时跳过（继续执行）
})
```

---
添加边
静态边（一对一 / 一对多）

```go
// 顺序边：A → B
g.AddEdge("nodeA", "nodeB")
// 并行边：A → B 和 C 同时执行
g.AddEdge("nodeA", "nodeB", "nodeC")
// 到终点
g.AddEdge("lastNode", schema.END)
```

条件边

```go
// Conditional 类型：func(ctx, nctx) ([]string, error)
g.AddConditionalEdge("router", func(ctx context.Context, nctx schema.Context) ([]string, error) {
    category := nctx.Get("category").(string)
    switch category {
    case "urgent":
        return []string{"urgent_handler"}, nil
    case "normal":
        return []string{"normal_handler"}, nil
    default:
        return []string{"default_handler"}, nil
    }
})
```

设置入口点

```go
g.SetEntryPoint("first_node")
```

---
Pipeline 快捷方法
Pipeline 快速创建顺序执行流水线，自动设置节点、边和入口点：

```go
nodeA := &schema.Node{Name: "step1", Func: step1Func}
nodeB := &schema.Node{Name: "step2", Func: step2Func}
nodeC := &schema.Node{Name: "step3", Func: step3Func}
// 等价于：AddNode(A,B,C) + AddEdge(A→B) + AddEdge(B→C) + AddEdge(C→END) + SetEntryPoint(A)
g.Pipeline(nodeA, nodeB, nodeC)
```

---
编译

```go
app, err := g.Compile()
if err != nil {
    // 可能的错误：
    // ErrEntryPointNotSet  - 未设置入口点
    // ErrNodeNotFound      - 边引用了不存在的节点
    // ErrInvalidGraph      - 图结构非法
    panic(err)
}
```

---
执行

```go
// Invoke 向图中注入初始消息并执行
err = app.Invoke(ctx, schema.ChatCompletionMessage{
    Role:    schema.ChatMessageRoleUser,
    Content: "用户的查询",
})
if err != nil {
    log.Error(err)
}
```

Invoke 的执行流程：
1. 将初始消息加入 Context
2. 触发 GraphStartCallback
3. 检查是否从中断恢复（InterruptionTypeStop），若是则从 InterruptionState.CurrentNode 重新开始
4. 递归执行节点
5. 节点完成后调用 AutoCompaction
6. 调用 Context.Release()
7. 触发 GraphEndCallback

---
完整示例：三步流水线

```go
package main
import (
    "context"
    "fmt"
    "code.byted.org/ad/nexus/context/nexuscontext"
    "code.byted.org/ad/nexus/schema"
)
func main() {
    ctx := context.Background()
    nctx := &nexuscontext.NexusContext{}
    g := schema.NewGraph(nctx)
    // 节点 1：预处理
    g.AddNode("preprocess", func(ctx context.Context, nctx schema.Context,
        reg func(func(schema.Context)), cb schema.Callback) (*schema.Command, error) {
        nctx.Set("processed", "预处理完成")
        fmt.Println("[Step 1] 预处理")
        return nil, nil
    })
    // 节点 2：主逻辑
    g.AddNode("main_logic", func(ctx context.Context, nctx schema.Context,
        reg func(func(schema.Context)), cb schema.Callback) (*schema.Command, error) {
        input := nctx.Get("processed").(string)
        nctx.Set("result", input+" → 主逻辑处理完成")
        fmt.Println("[Step 2] 主逻辑")
        return nil, nil
    })
    // 节点 3：后处理
    g.AddNode("postprocess", func(ctx context.Context, nctx schema.Context,
        reg func(func(schema.Context)), cb schema.Callback) (*schema.Command, error) {
        result := nctx.Get("result").(string)
        fmt.Printf("[Step 3] 后处理，最终结果：%s\n", result)
        return nil, nil
    })
    // 顺序边
    g.AddEdge("preprocess", "main_logic")
    g.AddEdge("main_logic", "postprocess")
    g.AddEdge("postprocess", schema.END)
    g.SetEntryPoint("preprocess")
    app, err := g.Compile()
    if err != nil {
        panic(err)
    }
    err = app.Invoke(ctx, schema.ChatCompletionMessage{})
    if err != nil {
        panic(err)
    }
    fmt.Println("最终状态:", nctx.Map())
}
```

---
状态在节点间传递
所有节点通过共享的 nctx（Context）传递状态：

```go
// 节点 A：写入状态
nctx.Set("my_key", "my_value")
nctx.SetShared("global_key", 42)
// 节点 B（在 A 之后执行）：读取状态
value := nctx.Get("my_key").(string)
num, ok := nctx.GetShared("global_key")
```

---
图执行错误处理

```go
// 方式 1：节点出错，图终止（默认）
// NodeFunc 返回非 nil error → 图停止，Invoke 返回错误
// 方式 2：出错跳过（SkipOnError = true）
g.AddNode("optional", myFunc, schema.NodeConfig{SkipOnError: true})
// 节点出错时，图继续执行到下一个节点
// 方式 3：超时重试
g.AddNode("flaky", myFunc, schema.NodeConfig{
    Timeout:    10 * time.Second,
    MaxRetries: 3,
    RetryDelay: 1 * time.Second,
})
```

---
注意事项
1. 并发安全：AddNode、AddEdge 等方法有内部锁保护，可在多 goroutine 环境中安全调用（但通常不需要这样做）。
2. 入口点必须先注册：SetEntryPoint 设置的节点必须已通过 AddNode 注册，否则 Compile() 会返回错误。
3. END 是保留节点名：schema.END = "END" 不能作为普通节点名。
4. 编译后仍可修改：Compile() 后图可以继续修改（添加节点、边等），但需要重新 Compile()。
5. Context 线程安全：并行节点共享 Context，写入相同 key 时注意竞态条件。
