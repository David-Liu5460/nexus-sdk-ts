条件路由允许 Graph 在运行时动态决定执行流向，而不是在定义图结构时静态确定。nexus-sdk-ts 提供两种条件路由机制：**ConditionalEdge**（条件边）和 **Command.goto**（节点内部返回）。

> 本文是 [`2. 条件路由-ConditionalEdge.md`](./original/2.%20条件路由-ConditionalEdge.md)（Go 版）的 TypeScript 对应版本，基于 Bun + TS SDK 实际代码（`src/core/graph.ts`、`src/core/command.ts`、`src/core/application.ts`）编写。文末附 **Go ↔ TS API 映射表**，并标注两版的差异点。

---
路由优先级回顾（TS 实际行为）

TS 版的路由优先级在 `resolveNext`（`src/core/application.ts`）中裁决，从高到低为：

```
Middleware（全局拦截）       g.useMiddleware()，返回非空数组即短路
    ↓ 返回 undefined
Command.goto（节点内部返回）  return gotoNode("x")
    ↓ 无 goto
ConditionalEdge（条件函数）   g.addConditionalEdge("r", fn)
    ↓ 无条件边
静态 Edge（addEdge）          g.addEdge("A", "B")
    ↓ 无静态边
END（自动结束）
```

> 差异：Go 文档把 `Command.Goto` 列在 `GraphMiddleware` 之上；而 TS 版 `resolveNext` 中 **Middleware 优先级最高**（先于 `Command.goto`）。以 TS 源码为准。

---
ConditionalEdge

基础语法（TS）

```ts
import type { Context } from "nexus-sdk-ts";

// ConditionFunc 类型：同步返回 string | string[]，不带 error
type ConditionFunc = (ctx: Context) => string | string[];

// 添加条件边
g.addConditionalEdge(fromNode, condition);
```

> 差异：Go 的 `Conditional` 是 `func(ctx, nctx) ([]string, error)`——双上下文 + 返回 error；TS 的 `ConditionFunc` 只有一个 `ctx`，**同步**返回 `string | string[]`，**不返回 error**（需要报错时在函数内 `throw`）。

基本示例：多路分支

```ts
// 执行分类逻辑的节点：自身不决定路由，交给条件边
g.addNode({
  name: "classify",
  func: async (ctx) => {
    const sentiment = analyzeSentiment(ctx.get<string>("text")!);
    ctx.set("sentiment", sentiment);
    return null; // 返回 null = 让条件边决定路由
  },
});
g.addNode({ name: "positive_handler", func: positiveFunc });
g.addNode({ name: "negative_handler", func: negativeFunc });
g.addNode({ name: "neutral_handler", func: neutralFunc });

// 添加条件边：根据 ctx 中的状态选择下一跳
g.addConditionalEdge("classify", (ctx) => {
  switch (ctx.get<string>("sentiment")) {
    case "positive": return "positive_handler";
    case "negative": return "negative_handler";
    default:         return "neutral_handler";
  }
});
```

条件边返回多个节点（并行扇出）

返回数组时，这些节点会在下一波被 `Promise.all` 并发执行（见 `execute`，`src/core/application.ts`）。

```ts
g.addConditionalEdge("dispatcher", (ctx) => {
  const taskType = ctx.get<string>("task_type");
  if (taskType === "comprehensive") {
    // 同时执行三个分析（并发）
    return ["syntax_check", "semantic_check", "style_check"];
  }
  return "quick_check"; // 单个节点可直接返回 string
});
```

Command.goto 路由

`Command.goto` 在节点内部动态决定路由，优先级高于 ConditionalEdge（但低于 Middleware）：

```ts
import { gotoNode, gotoEnd } from "nexus-sdk-ts";

g.addNode({
  name: "agent_node",
  func: async (ctx) => {
    const resp = await myAgent.run(ctx);
    const answer = resp.choices[0].message.content;

    // 根据 LLM 输出决定路由
    if (answer.includes("需要人工审核")) {
      return gotoNode("human_review");
    }
    if (answer.includes("任务完成")) {
      return gotoEnd();
    }
    // 默认：返回 null，使用条件边 / 静态边
    return null;
  },
});
```

---
多路路由模式

模式 1：基于评分的路由（ConditionalEdge）

```ts
g.addConditionalEdge("evaluator", (ctx) => {
  const score = ctx.get<number>("quality_score")!;
  if (score >= 0.9) return "publish";    // 直接发布
  if (score >= 0.7) return "review";     // 人工审核
  return "regenerate";                   // 重新生成
});
```

模式 2：动态路由到任意节点（策略模式，Command.goto）

```ts
import { gotoNode } from "nexus-sdk-ts";

g.addNode({
  name: "strategy_node",
  func: async (ctx) => {
    // 从 Context 或 LLM 输出获取下一步
    const nextNode = ctx.get<string>("next_agent")!; // e.g. "agent_a" / "agent_b"
    return gotoNode(nextNode);
  },
});
```

模式 3：循环路由（Command.goto 指向自身）

```ts
import { gotoNode } from "nexus-sdk-ts";

g.addNode({
  name: "retry_node",
  func: async (ctx) => {
    const retries = (ctx.get<number>("retries") ?? 0) + 1;
    ctx.set("retries", retries);

    const result = tryOperation();
    if (result.ok || retries >= 3) {
      ctx.set("final_result", result);
      return gotoNode("output");
    }
    // 返回到自身重试
    return gotoNode("retry_node");
  },
});
g.setEntryPoint("retry_node");
```

> ⚠️ 自环依赖 `invoke` 的 `maxSteps`（默认 1000）兜底，务必保证有退出条件，否则达到上限会抛 `exceeded max steps`。

模式 4：基于 LLM 输出的路由（Command.goto）

```ts
import { gotoNode } from "nexus-sdk-ts";

g.addNode({
  name: "router_agent",
  func: async (ctx) => {
    // 让 LLM 决定路由（具体 Agent 构造见 src/agent/base.ts）
    const resp = await routerAgent.run(ctx);
    const nextNode = resp.choices[0].message.content.trim();
    return gotoNode(nextNode);
  },
});
```

---
ConditionalEdge vs Command 选择指南

| 场景 | 推荐方式 |
| --- | --- |
| 基于预先定义的固定条件 | ConditionalEdge |
| 节点执行后才能知道路由 | Command.goto |
| 需要 LLM 参与路由决策 | Command.goto（在节点内调用 LLM） |
| 基于共享状态的路由 | ConditionalEdge（读取 `ctx.getShared`） |
| 动态路由到未知节点 | Command.goto |
| 需要全局、跨节点统一拦截 | Middleware（`g.useMiddleware`，优先级最高） |

---
错误处理

TS 的 `ConditionFunc` 不返回 error，要中断流程就直接 `throw`——异常会沿 `invoke` 向上 reject。

```ts
g.addConditionalEdge("check", (ctx) => {
  const value = ctx.getShared<unknown>("result");
  if (value === undefined) {
    // 抛出异常 => invoke() reject
    throw new Error("result not found in context");
  }
  if (typeof value !== "number") {
    throw new Error(`invalid score type: ${typeof value}`);
  }
  return value > 0.8 ? "pass" : "fail";
});
```

> 差异：Go 通过返回 `(nil, error)` 让 `Invoke` 失败；TS 没有 error 返回值，统一用 `throw`。

---
注意事项

1. **每个节点只能有一条条件边**：`addConditionalEdge` 基于 `Map.set`，对同一节点重复调用会**覆盖**上一个条件边（`src/core/graph.ts`）。
2. **条件边优先于静态边**：节点同时有条件边和静态边时，条件边先生效（见 `resolveNext` 顺序）。
3. **空数组的行为差异**：Go 中条件函数返回空列表会**回退到静态边**；**TS 不会**——`resolveNext` 命中条件边后直接返回其结果，返回 `[]` 则该节点本波没有下一跳（不会再落到静态边）。需要走静态边时应让节点返回 `null`、**不要注册条件边**，或在条件函数内显式返回目标节点名。
4. **条件函数同步、不并发**：`ConditionFunc` 是同步函数（返回 `string | string[]`，非 Promise），在 `resolveNext` 中逐节点顺序调用，不会被并发调用。
5. **避免无限循环**：用 `Command.goto` 或条件边构造循环时务必有退出条件；`invoke` 的 `maxSteps`（默认 1000）是防御性上限，触发即抛错。
6. **Middleware 凌驾其上**：注册了 Middleware 时，它会先于 `Command.goto` 和条件边裁决（返回非空数组即短路），可用于全局改道。

Go ↔ TS API 映射表

| Go API | TS API |
| --- | --- |
| `type Conditional func(ctx, nctx) ([]string, error)` | `type ConditionFunc = (ctx: Context) => string \| string[]` —— 单 ctx、同步、无 error |
| `g.AddConditionalEdge("r", fn)` | `g.addConditionalEdge("r", fn)` |
| `return []string{"a"}, nil` | `return "a"` 或 `return ["a"]` |
| `return []string{"a","b"}, nil`（并行） | `return ["a", "b"]`（并发扇出） |
| `return nil, err`（条件函数报错） | `throw new Error(...)` |
| `return schema.GotoNode("x"), nil` | `return gotoNode("x")` |
| `return schema.GotoEnd(), nil` | `return gotoEnd()` |
| `return nil, nil`（用边路由） | `return null` |
| `nctx.Get("k").(string)` | `ctx.get<string>("k")` |
| `nctx.GetShared("k")` | `ctx.getShared<T>("k")` |
| 优先级：`Command.Goto > Middleware > Conditional > Edge > END` | 优先级：`Middleware > Command.goto > 条件边 > 静态边 > END` |
| 空列表回退静态边 | **不回退**（命中条件边即返回其结果） |
